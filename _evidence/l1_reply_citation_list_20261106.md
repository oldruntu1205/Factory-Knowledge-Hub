**裁决：同意方案 A，按以下口径实施。** 本次批准的是“答案附证据清单”的可信边界：引用提供来源追溯，**不代表系统已经验证每个实质句均受证据支持**。

材料足以支持放宽协议，但不足以证明问题“与检索/治理无关”；该结论应收窄为：当前样本中，严格内联引用协议造成了明显的可用性阻塞。

1. **引用行剥离：同意。**  
   先提取、校验引用，再从展示正文剥离协议规定的末尾引用行；`citations` 是权威引用字段。不要通过全局删除“引用：”或 UUID 的方式处理正文。兼容内联引用时，展示层应将有效标记转换为用户可读的引用标记，避免裸露内部 id。

2. **逐句覆盖退出状态判定：同意。**  
   不增加“引用数少于段落数”等替代闸门：引用数量不能证明支持程度，一条证据可以支持多段，多条证据也可能不支持答案。  
   原逐句检查最多作为“内联标注完整度”诊断；在清单协议下，**不能继续把它称为证据覆盖率**。若保留提示，应说明检查的是标注格式，不是事实支持程度。

3. **`引用：无`：本切片按零有效引用处理，要求人工复核。**  
   保持统一规则：有检索证据，但模型没有提供有效引用 → `REFUSED / INSUFFICIENT_EVIDENCE` + 人工。仅凭模型写“无”，不足以判断这是正确拒答还是引用失败。无检索证据仍走既有 `NO_EVIDENCE`，不调用模型。  
   补一条冲突口径：清单写“无”但内联存在合法引用时，按合并后的有效引用集合判断；“无”不覆盖已提取的合法引用，同时记录协议冲突。

4. **伪造 id：维持 `HUMAN_REVIEW_REQUIRED`，无需新增来源类别。**  
   清单与内联采用相同白名单校验；任一来源出现白名单外 id 都触发人工，不能因另一来源有合法 id 而忽略。合法引用可以保留供复核，但不得因此返回 `ANSWERED`。来源差异可留作诊断信息，无需新增状态或拒答码。

5. **审计：同意不加列，但不赞成只留一个笼统原因。**  
   `refusal_code` 保持现有契约；在现有 `route_reason` 可承载的范围内，区分“引用行缺失且无内联引用”“显式无引用”“正文为空”“非法引用”。缺失引用行但存在合法内联引用属于兼容成功，不应记录为拒答。无需为此扩展表结构。
