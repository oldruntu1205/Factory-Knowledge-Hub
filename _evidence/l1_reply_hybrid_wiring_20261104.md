**Q1 → 裁决：A，但按破坏性契约变更管理。** 理由：响应必须如实标识算法；扩大响应取值集合会使按旧 `const` 校验的调用方失败，不能宣称向后兼容。授权修改契约，但混合模式启用前必须完成受影响调用方的兼容确认；若要求既有 v1 契约绝对不变，则应改选 C。

必须补的断言：纯词法返回 `lexical-v1`，实际执行双路融合才返回 `hybrid-rrf-v1`；真实响应通过对应 JSON Schema 校验；OpenAPI 与 Schema 取值一致；端点描述准确区分两种模式。不能只断言响应键集合。

**Q2 → 裁决：默认纯词法，通过服务端开关 opt-in；区分“未启用能力”与“已承诺能力故障”。** 理由：默认 `provider=none` 应保留已有词法能力；显式启用 hybrid 后缺模型、配置矛盾或推理失败，应阻止就绪或返回 503，不能静默降级。

必须补的断言：默认配置保持词法行为；显式 hybrid 配合 `provider=none`、依赖缺失、权重缺失或推理失败，均不返回伪成功；纯词法无需加载模型依赖；生产配置拒绝测试 embedder。真实 BGE-M3 验证和代表性语料评估完成前，不授权生产启用混合模式。

**Q3 → 裁决：必须记录实际执行的召回模式，本切片增加迁移 0011。** 理由：模式属于执行配置事实，与候选数量、过滤结果所泄露的内容存在性不同，不冲突；不能将审计补齐推迟到启用之后。

必须补的断言：审计模式采用有限枚举，能区分 `lexical-v1` 与 `hybrid-rrf-v1`；成功响应与已提交审计中的模式一致；审计提交失败不得返回成功；失败路径不伪记为成功执行某模式。历史记录仅在有依据时回填词法模式；继续禁止原始 query、候选数和全部过滤标志，保留 HMAC 规则。

**Q4 → 裁决：接受应用层 ACL，不要求改为 SQL 前置细粒度过滤，也不增加逐请求越权计数。** 理由：按既有判决，可信服务进程内的候选处理可以包含待授权内容，但授权必须覆盖所有输出及后续消费边界；“不返回正文”本身不足以证明没有泄露。

必须补的断言：无权 chunk 不进入结果、context、对外调试信息、日志或持久化缓存；两路命中及重复命中均不能绕过 ACL；授权过滤先于最终截断和上下文装配；撤销后发起的检索不可返回该内容；空结果与全部无权保持相同外部表达。不新增候选拒绝数、过滤比例或据此触发的逐请求告警。

涉及 ADR-04/06 **尚未明确裁决的权限细节，待 ADR 裁决**；可先行沿用题述已裁决口径，遇到授权歧义拒绝该候选。此裁决不等于宣称排名、条数或时延具有严格的侧信道不可区分性。

**Q5 → 裁决：不要求两路同深度，本切片保留现有深度。** 理由：召回深度是排序策略，RRF 不要求两路等长；深度不对称与“返回上限、不保证填满”不冲突，但该表述也不保证召回质量。

必须补的断言：向量候选上限符合 `min(max_results×4, 200)`，词法路符合现有上限；RRF 使用排名和 `k=60`；单路为空仍能正确融合；去重和 ACL 后返回数不超过 `max_results`，允许不足或为空。不得为填满结果放宽权限或可见性。

**Q6 → 裁决：授权 L2 在本切片同步修改契约与断言，随切片送终审。** 理由：运行时、对外文档和可执行断言必须作为同一变更交付，无需等待 L1 另写测试代码。

必须补的断言：同时覆盖 `contracts/openapi/openapi.yaml`、`contracts/schema/search_response.json`、`tests/contract` 及端点实际响应值；包含词法成功、混合成功、模型不可用、权限过滤和审计失败路径。终审材料必须标明 Q1 的兼容影响与启用条件；现有绿色测试不能替代新增断言。

**Q7 → 裁决：本切片仅授权 search 的混合模式；context 明确保留词法召回。** 理由：候选来源变化可能改变拒答分档，在真实模型和证据质量尚未验证时，共享 `SearchService` 不能成为隐式扩大变更范围的依据。

必须补的断言：启用 search 混合模式后，context 仍使用词法召回；`NO_EVIDENCE`、`INSUFFICIENT_EVIDENCE`、`HUMAN_REVIEW_REQUIRED` 的既有触发语义保持不变。context 接入混合检索须另行送审并补充分档回归；不能直接沿用词法分数阈值解释 RRF 分数，也不在本切片凭空新增阈值。
