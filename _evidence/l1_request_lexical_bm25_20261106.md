# 设计稿：词法排序升级（BM25 字级重排，`lexical-v3`）

- 日期：2026-11-06
- 提出方：L2 实施
- 风险归类命中：**检索打分语义变化**（所有描述类召回）、**审计枚举迁移**
- 请只做判断：**不要探索仓库、不要读源码、不要跑测试**。

## 1. 问题（已有实测）

客户目录（85 页 / 111 个 child 块）上，词法召回 `recall@10` 对货号类查询是 0/30，
描述类查询则出现"该召回的排不进来"：

- 「试管」是判别词，但「有哪些规格的试管？」的 top-5 全是**冷凝管样板段落**（每页重复同一句话：
  "高硼硅精选管材，车床焊接工艺……以下规格均为常用规格"）；
- 直接查「试管」时，第 76 页的试管块也只能排到第 3；
- 根因：**字级 OR + `ts_rank_cd` 没有 IDF**——高频字（的/管/规格）在样板段落里反复出现，
  把分数堆高；判别字（试/管）没有额外价值。

## 2. 原型实验（离线，不改代码）

在同一份语料上按三种方式排序，看"目标块"的名次：

| 查询 | 需命中片段 | 现有 `ts_rank_cd` | IDF 加权 | **BM25（k1=1.2,b=0.75）** |
|---|---|---|---|---|
| 有哪些规格的试管？ | 试管 | 未进 top-5 | 第 2 | **第 1** |
| 冷凝管的标口范围是多少？ | 14-70mm | 第 2 | 第 3 | 第 3 |
| 塞子的标口有哪些规格？ | 塞 | 第 1 | 第 1 | 第 1 |
| 冷凝管 | 冷凝管 | 第 1 | 第 1 | 第 1 |
| 培养皿有哪些规格？ | 培养皿 | 第 1 | 第 1 | 第 1 |

结论：**BM25 字级重排能修掉试管这条，且不影响其余查询**；IDF 也能修，但效果略弱。

## 3. 拟议实现

1. 候选集**不变**：仍用现有 `lexeme @@ websearch_to_tsquery`（GIN 索引）取候选，
   窗口上限 200 条（现有 `OVERFETCH × max_results` 之上再加一个绝对上限）。
2. **重排**：对候选窗口内每条算 BM25（字级 token = `segment_cjk`，与入库一致）：
   `score = Σ idf(t) · tf·(k1+1) / (tf + k1·(1 - b + b·len/avg_len))`
3. `idf(t) = ln((N - df + 0.5)/(df + 0.5) + 1)`；`df` 用**SQL 逐词查**（每个 query 去重字 ~5–10 个，
   走同一 GIN 索引 + 同样的可见性谓词），`N` 用同一谓词下的块数。**不新增统计表**。
4. 打分标识改为 `lexical-v3`，写入 `retrieval_queries.scoring`（**需要迁移 0016 放宽枚举**）。
5. 混合模式：BM25 分数参与现有 RRF 融合（按名次而非分值，RRF 对量纲不敏感，理论上安全）。

## 4. 待判问题

1. **候选窗口 200** 是否足够？（原型里目标块都在前 5；但极端查询可能在窗外。）
   是否需要自适应窗口（如按 df 估计）？
2. **df 用 SQL 逐词查**（不建统计表）是否可接受？代价：每个查询多 5–10 次 GIN count，
   换来零 schema 变更。若要建物化统计表，需要新迁移 + 刷新策略，本切片不做。
3. **k1/b 是否做成配置**（默认 1.2 / 0.75），还是先写死？
4. **审计枚举**：`retrieval_queries.scoring` 现允许 `lexical-v2`，需迁移 0016 增加 `lexical-v3`。
   是否同意本切片带一个小迁移？（回滚：删枚举值前需确认无存量数据，按既有纪律"有数据拒绝"）

## 5. 实施侧要补的断言

1. 「有哪些规格的试管？」的 top-3 命中试管块（本次问题的直接回归）；
2. 其余 4 条查询的名次不劣化（冷凝管/塞子/培养皿/标口范围）；
3. BM25 参数边界：空查询、单字查询、无候选、全停用字；
4. 候选窗口截断时行为明确（拿到 200 条就按重排取 top-k，不静默扩容）；
5. 可见性谓词与现有实现完全一致（租户/scope/状态/ACL 不变）；
6. 审计 `scoring=lexical-v3`，且迁移回滚在无存量数据时可用；
7. 现有 477 项测试全绿；recall 基准（文档语料 30 条）v2 vs v3 对比数字入档；
8. 结构化通道不受影响（不经过检索）。

## 6. 影响面与风险

- **影响**：所有词法/混合检索的排序（描述类回答的检索质量）；货号类走结构化通道不受影响；
- **性能**：多 5–10 次 GIN count + 200 条内存重排，预估 <10ms（原型未测线上耗时）；
- **风险**：窗口截断导致长尾查询仍召回失败；df 逐词查询在超大租户下变慢；混合模式融合口径需复测。
