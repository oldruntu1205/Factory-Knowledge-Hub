## 1. 四项改动与理由

### 1.1 客户规格问答不再带单价（P0-2）

复现：公开审批过的 C0 目录，客户问「A112420 的规格是什么？」→ 目录精确通道回答
**「规格为 200mm 38*300 24*24；单价 39.00（CNY）」**。规格可自动答，价格不可。

改动：外部客户（`is_external_customer`）走目录通道时答案只含规格；
price 意图分支对客户加防御纵深——即使漏到分支也转人工（`HUMAN_REVIEW_REQUIRED`）。
内部身份的单价查询保持原样。

回归（`tests/e2e/test_customer_visibility.py`，真实 PG + HTTP）：
公开审批前不可读（目录 409/检索空/证据 403）、发布后规格可答且不含价格、
撤销后三路失效、旧引用直读 403、内部单价仍可答。

### 1.2 培训问答限定课程源（新）

改动：检索新增 `version_ids` 过滤（lexical / dense / hybrid 三路同一谓词），
`/v1/training/ask` 先取"当前任务绑定且仍 APPROVED_INTERNAL 的课程源版本"，
再以该集合作为召回与引用白名单。
验收：同租户两门课，学员 A 在课程 A 的任务里问课程 B 的事实 → 引用不含 B 的版本、答案不含 B 的事实。

### 1.3 导师签核的可信授权（迁移 0021）

原状：只要持 `mentor` scope，就能签任何同租户任务，也无法拒绝"学员签自己"。

改动：新表 `training_mentor_scopes(tenant, mentor_subject_id, cohort_id | role_id)`，
一条授权只能是班组**或**岗位（禁止两者都空=可签全部）。签核时：
任务必须是本人 grade 之外的可信范围——**导师须被授权到任务的 cohort，或课程的 role**；
学员 `sub` 等于签核人 `sub` → 拒绝。三者均返回 403（不区分原因）。
实操结论仍单独记录在 `training_practical_signoffs`。

### 1.4 关键 HTTP 验收改用业务角色（发现并修了一个真实缺陷）

原验收用 `postgres`（表 owner）连接跑 API，owner 绕过 RLS，**测出来的隔离是假的**。

新验收：迁移/造数用管理员连接；API 用 `fkh_app_test`（LOGIN、非 superuser、非 owner、
无 BYPASSRLS）；并直接断言"未绑定租户时该角色看不到任何 `knowledge_chunks`"。

过程中发现真实缺陷：检索与审计路径里有显式 commit（审计必须先落库），
事务级 GUC（`set_config(..., true)`）随事务结束消失，之后的 `rag_queries` 写入
撞 RLS `WITH CHECK` → 500。已改为**请求级会话级绑定**（`set_config(..., false)`），
并在连接归还前清除（避免连接复用串租户）。

## 2. 需要你判断的四点

1. **规格可答、价格不可答**的边界是否认可？我按"规格=产品事实、价格=商务承诺"切分。
   目录条目的**证据**（公开文档原文）里仍含价格，因为该文档本身就是公开内容——
   客户点开原文能看到价格。若要求连证据也屏蔽，需要"字段级证据裁剪"，这是新契约，请裁决。
2. **培训问答限定课程源**是否过严？现在学员只能问本任务课程源内的内容，
   跨课程的综合问题会被拒（`INSUFFICIENT_EVIDENCE`）。若希望允许"同岗位多课程"，需扩白名单口径。
3. **导师授权模型**：班组或岗位二选一。是否需要"部门级导师"或"多岗位一人授权"？
   现在一条记录只覆盖一个目标，多目标需多行（我认为够用）。
4. **会话级 GUC 绑定**：改动把租户绑定从"查询级 local"提升为"请求级 session + 归还前清除"。
   这是同一连接内多事务也能保持租户上下文的必要修复，但也意味着**任何绕过 `get_conn`
   直接拿池连接的新代码都必须自己绑定/清除**。是否接受这一约束（或要求我把它收进
   统一的连接工厂，禁止裸用 pool）？
