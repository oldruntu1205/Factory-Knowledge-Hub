## 1. 为什么必须改

整份目录验收（`_evidence/catalog_acceptance_20261106.md`）：

- 结构化通道（货号/报价）：20/20 答对、各 1 条引用、0ms，**无模型参与** → 可验收；
- 描述类问答：8 题 **ANSWERED 0/8、带引用 0/8**，但**内容关键词 6/8 是对的**。

换模型复测（同 4 题）：

| 模型 | ANSWERED | 带引用 |
|---|---|---|
| qwen3:14b | 0/4 | 0/4 |
| qwen3:8b | 0/4 | 0/4 |
| qwen2.5:7b | 0/4 | 0/4 |
| qwen2.5-coder:14b | 0/4 | 0/4 |

结论：**"每个实质句都必须内联 `[evidence_id]`" 这条协议在 7B–14B 上不成立**，
与检索/治理无关；现行规则因此把"内容正确但没有内联标记"的回答全部降级为拒答。

## 2. 拟议改动（方案 A）

1. **提示词**：正文之后必须另起一行，只写
   `引用：<evidence_id> <evidence_id> …`；证据不足时写 `引用：无`。
   保留现有防注入规则（证据内指令一律当资料）与"只能引用给定 id"。
2. **解析**：只从**最终答案**里取（qwen3 的 `thinking` 是独立字段，不进答案）：
   - 优先取末尾 `引用：` 行中的 id；
   - 兼容仍在内联写 `[id]` 的回答，二者合并去重；
   - **把 `引用：` 行从展示正文中剥离**，避免用户看到一串 UUID。
3. **覆盖判定**：
   - **取消**"存在无引用句子 → 拒答"的降级；
   - 保留：无证据 → `NO_EVIDENCE`（不调模型）；有证据零引用 → `INSUFFICIENT_EVIDENCE` + 人工；
   - **保留**：出现白名单外 id → `HUMAN_REVIEW_REQUIRED`（伪造仍拦截）；
   - 新增：剥离引用行后正文为空 → `INSUFFICIENT_EVIDENCE` + 人工。
4. **不变**：审计字段、`ANSWERED` 必须 ≥1 条引用这条契约、`version_id/locator` 取系统侧。

## 3. 待判问题

1. `引用：` 行从正文剥离是否合适？（我倾向剥离：它是元数据，不是回答内容；契约的 `citations` 字段才是权威。）
2. **逐句覆盖检查降为"仅提示"**是否可接受？我的理解：它从"闸门"降为"质量指标"，
   不再参与状态判定；若你认为需要保留一个更弱的拦截（例如"引用数明显少于段落数 → 转人工"），请给口径。
3. `引用：无` 的处理：视同零有效引用（`REFUSED/INSUFFICIENT_EVIDENCE` + 人工复核）是否合适？
   还是应当作为正常拒答（不要求人工）？
4. 伪造 id 仍走 `HUMAN_REVIEW_REQUIRED`（保留可用引用），是否需要额外区分"清单行伪造"与"内联伪造"？
5. 是否需要把"引用行缺失/为无"这类情况写进审计？
   现有 `rag_queries` 只有 `refusal_code`/`route_reason`，我倾向不加列：用 `INSUFFICIENT_EVIDENCE` 表达即可。

## 4. 实施侧要补/改的断言（供裁剪）

1. 提示词包含 `引用：` 指令与"引用：无"约定；
2. 解析：末尾清单行 / 内联 `[id]` / 两者混合 / 完全无引用 四种情况；
3. 展示正文已剥离引用行（不含 UUID 与"引用："字样）；
4. 有证据 + 清单里 1 条合法 id + 多个未标注句子 → **ANSWERED**（记录放宽后的行为）；
5. 清单里出现伪造 id → `HUMAN_REVIEW_REQUIRED`（伪造仍拦）；
6. 清单写"无" → `REFUSED/INSUFFICIENT_EVIDENCE`；
7. 剥离后正文为空 → `INSUFFICIENT_EVIDENCE` + 人工；
8. 无证据时不调用模型（既有断言不变）；
9. 审计与引用行数与契约不变（一次成功问答恰好一条 `rag_queries`，引用按条记账）；
10. 结构化通道不受影响（回归）。
