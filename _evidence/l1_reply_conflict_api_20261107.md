**裁决：有条件通过。** 按下列口径补齐契约后可实施，无需再增加一次设计审批。本判断仅依据所提供的设计稿，未探索仓库、读取源码或运行测试。

1. **权限：读用 `catalog.read`，决议另需 `catalog.resolve`。**

   GET 要求 `catalog.read`；POST 同时要求 `catalog.read` 和 `catalog.resolve`，并满足资源自身的 `required_scope` 与 ACL。`catalog.read` 若尚不存在，随本片登记。

   不复用 `knowledge.review` 或 `knowledge.search`：文档审核、知识检索都不应自动获得目录冲突的读取或决议权限。scope 定义、令牌签发侧和 OpenAPI 必须一起更新；既有令牌不能自动获得新权限。

   **活跃 user 限制用于 POST。** GET 沿用既有读取主体规则，不额外禁止具备读取权限的 service/agent。POST 的身份来自已验证令牌，并由服务端执行 `require_operator`、确认主体当前仍活跃，不能只信签发时的活跃状态。

2. **列表可见性：接受，但必须先过滤，再计数和分页。**

   租户、版本可操作状态、资源 `required_scope`、ACL 均满足后，才参与 `total`、排序及分页。不能先取一页再剔除不可见组，否则会出现空洞、计数泄露和分页遗漏。

   `status=KEEP|DROP_ALL` 仍可查询，但也受上述版本过滤。因此本接口不承担已撤销、弃用、被替代版本的历史审计查询。

3. **资源级拒绝统一 404；调用资格不足返回 403。**

   - 未认证或令牌无效：沿用既有 401。
   - 缺端点 scope、POST 非 user 或主体已停用：403 `ACCESS_DENIED`，与具体 `group_id` 无关。
   - 不存在、跨租户、资源 `required_scope` 不满足或 ACL 拒绝：统一 404 `NOT_FOUND`，错误体不透露具体原因。

   **必须修正设计稿中“不可见”和“版本不可操作”的混用：** POST 先按租户和资源读取权限判断是否应返回 404；资源获准访问后，版本不在 `OPERABLE_STATUSES` 才返回 409。否则撤销版本会被提前隐藏，拟议的版本冲突错误就无法成立。

   本片采用上述 404 策略，不顺带修改 `routes_review`；其既有 403 不作为新接口必须复制的规则。

4. **重复决议：409，复用 `VERSION_CONFLICT`。**

   不新增 `ALREADY_RESOLVED`。即使 action、候选与第一次完全相同，也返回 409；第二次不得更新任何决议字段。前端遇到网络结果不明，可重新读取状态。

   已获准访问但版本不可操作，同样返回 409 `VERSION_CONFLICT`。`KEEP` 候选不属于该组返回 422 `VALIDATION_ERROR`，不得透露候选究竟不存在还是属于其他组。归属检查必须在已授权的组内进行。

5. **本片默认不返回 `raw_text`。**

   返回 `spec/raw_price/locator`，其中 `raw_price` 必须属于调用者既有授权可读的字段。省掉原文并不能替代价格字段本身的授权。

   “内网”和组 ACL 过滤不足以单独证明整行原文可披露；原文还可能包含列表未定义的其他信息。本片没有展示整行原文的必要，先采用最小响应即可。

6. **分页参数接受；排序补为 `code ASC, group_id ASC`。**

   `code` 不能单独保证稳定顺序，必须增加唯一的次级排序键。

   `limit` 为整数且范围为 1–200，默认 50；`offset` 为非负整数，默认 0。非法值和非法 `status` 返回 422；超出 `total` 返回空列表及真实可见总数。

   offset 分页可用于本片，但并发决议会使 OPEN 集合变化，跨请求可能出现遗漏或重复；本片不承诺浏览期间的快照一致性，也不因此扩成游标分页。

7. **本片不新增审计事件。**

   现有需求没有必须由事件驱动的下游，不要求增加 `catalog.conflict.resolved.v1`。

   前提是组决议在同一事务内持久记录状态、操作者稳定标识、服务端时间、备注，且禁止原地改写。**KEEP 还必须能从组决议明确恢复所选 `candidate_id`**；若已有对应字段，直接复用，并在决议响应中返回，`DROP_ALL` 时为 null。仅有 `KEEP` 状态无法说明保留了谁。

   组行可以承担本片的业务决议记录，但不据此宣称已具备独立、防篡改的审计日志。
