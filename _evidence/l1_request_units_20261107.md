# L1 送审：一致性检查查不到「压力/时间/倍数」类数值（ANSWERED + 引用 + 编造）

- 日期：2026-11-07
- 触发：本片原计划修「证据片段截断」，实测发现截断**不是**该问法的原因；真正的问题是
  `literal-support-v3` 的单位白名单不含 MPa/秒/倍，导致编造的验收压力被判 ANSWERED。
- 请只做判断：**不要探索仓库、不要读源码、不要跑测试**。

## 1. 最小复现（真实系统、真实模型、3 次一致）

问题：`气密性测试要充气到多少压力？`
知识库原文（第 1 条证据，完整块，未被截断）：

```
气密性测试：将冷凝管两端封堵后充气至 0.2MPa，保压 60 秒，压力下降不超过 5% 为合格。
```

实际返回：

```
status = ANSWERED
citations = 1
answer = 气密性测试需要根据具体的设备和使用场景来确定充气压力，一般情况下，
         测试压力通常为设备工作压力的 1.5倍或更高，以确保设备在正常工作压力下具有良好的密封性能。
         具体数值应参考设备的技术参数或相关行业标准。
claim_check = 空（未提取到任何 claim）
```

即：**证据里写 0.2MPa，答案写 1.5 倍工作压力，系统判定 ANSWERED 并附上一条真实引用。**
引用让这个编造值看起来"有据可查"，这是本系统最不能接受的一类输出。

同批对照（同一证据、同一模型）：

| 问法 | 结果 |
|---|---|
| `保压时间是多久？` | ANSWERED，60 秒（正确，证据有） |
| `气密性测试充气压力是多少 MPa` | REFUSED / INSUFFICIENT_EVIDENCE（证据明明有 0.2MPa，模型自己说没写） |
| `气密性测试要充气到多少压力？` | **ANSWERED + 编造 1.5 倍**（本文问题） |

## 2. 定位（确定性，已逐条核对）

`fkh/answer/consistency.py`：

```python
RULE_VERSION = "literal-support-v3"
_UNITS = ("kg", "mm", "cm", "ml", "g", "l", "L", "%", "℃", "元", "只/箱")
_NUM = r"\d+(?:\.\d+)?"
_SINGLE = re.compile(rf"(?<![\d.])({_NUM})\s*({_UNIT_PATTERN})")
```

- `1.5倍` 的"倍"不在白名单 → 不构成 claim；
- `0.2MPa` 的 MPa 不在白名单 → 即使答案写对了也核不了；
- 同理 `60 秒`、`5%`（% 在，但答案未提百分比故未触发）、`kPa/bar/N·m/rpm` 全部在检查之外。

结论：**凡是不在 11 个单位白名单里的量纲，一致性检查等于没开。** 制造业知识库里压力、时间、转速、扭矩、电压恰恰是最常见的量。

## 3. 拟议改动（请裁决口径，不要直接同意）

1. 扩充单位白名单（候选，按本行业实际）：
   `MPa, kPa, Pa, bar, kgf, N·m, Nm, s, 秒, min, 分钟, h, 小时, 倍, rpm, V, A, kW, W, °C, 目, 号`
   —— 每条都要考虑：会不会与货号/规格里的数字串混淆？`号`、`目` 这类弱单位是否值得纳入？
2. 明确"倍数/百分比"的语义：`1.5倍` 与正文里的 `1.5`、`150%` 是否等价？等价声明由谁负责？
3. 单位白名单扩容后，是否仍需**列对齐**（现有 `_unit_belongs_to_cell`）？我倾向：
   - 单值（`0.2MPa`、`60秒`）：要求"数值+单位"字面出现在**被引用证据**中（现口径不变，仅扩单位）；
   - 区间/尺寸（`14-70mm`）：仍要求列对齐；
   - `倍`：要求在证据里字面出现"X倍"或以百分比形式出现，不做语义换算。
4. 版本号：是否升 `literal-support-v4`（改了单位集合 = 判定语义变化，按既往惯例应升）。
