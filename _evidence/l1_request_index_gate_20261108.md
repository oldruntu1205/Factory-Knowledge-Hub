# L1 终审：索引发布闸门与撤销后重建收敛（Rev2 §7.2）

- 日期：2026-11-08
- 提交：`eb612af`；迁移 `0022` / `0023` / `0024`
- 风险归类：**DB 迁移**、**可见性语义**、**撤销不可逆性**
- 请只做判断：**不要探索仓库、不要读源码、不要跑测试**。

## 1. 原状与要解决的问题

- 索引代（`index_generation`）在入库时分配，但**发布不看它**：只要状态翻成
  `APPROVED_INTERNAL`，检索立刻可见；没有"构建完成才可发布"的闸门。
- 撤销后块永远留在库里：`rag_citations` 对 `knowledge_chunks` 是 RESTRICT 外键，
  历史引用会阻止删除。§8.4 要求"撤销后旧引用不能继续泄露"——API 层已拒，
  但物理上内容未收敛。

## 2. 改动

### 2.1 迁移 `0022`：两张小表

- `index_generations(tenant, generation, status, chunk_count)`，状态 `BUILDING/READY/FAILED`
- `index_visibility(tenant, generation)` = 可见代**水位**
- 回填：现有块视为 READY，水位 = 现存最大代（升级后行为不变）

### 2.2 发布闸门

- 入库：切片写入后把该代标 `READY`，**不**推进水位；
- 发布（`APPROVED_INTERNAL` / `PUBLISHED_PUBLIC`）：校验该版本所有块所属代 `READY`
  → 再 `GREATEST(旧, 新)` 原子推进水位；未就绪 → 409，版本停在原状态；
- 检索（词法 / 混合 / 目录）：**公开内容**额外要求 `index_generation <= 水位`；
  水位缺失按 0（= 尚未切换，公开不可见）。内部内容不加水位限制。

> 取舍理由：内部草稿/待评版本本就被状态挡住；若对内部也加水位，会把"检索机制"类
> 用例全部打死，属于把闸门放错位置。公开面是唯一对外承诺，闸门放这里。

### 2.3 撤销与收敛

- 撤销：状态同步改 `REVOKED`、写 outbox；API 立即拒绝（问答/检索/证据），**不阻塞**物理清理；
- `rebuild_visible_generation`：删除 `REVOKED`/`DISCARDED` 的块 → 切新代 READY → 推进水位；
- 迁移 `0023`：`rag_citations.chunk_id` 允许 NULL、外键改 `ON DELETE SET NULL`；
- 迁移 `0024`：复合外键整体置空会连 `tenant_id` 一起置空（撞 NOT NULL，实测），
  改为 PG15+ 列级写法 `ON DELETE SET NULL (chunk_id)`——审计保留 `version_id`/`locator`。

## 3. 验收（真实 PG + HTTP，`tests/e2e/test_index_gate.py` 4 条）

| 场景 | 断言 |
|---|---|
| 索引代标 FAILED 后发布 | 409 `VERSION_CONFLICT`，版本仍 `REVIEWED`（没有半发布） |
| 发布成功 | 水位 = 该版本代 |
| 水位回退（删水位行） | 公开检索立刻为空（旧代不泄露） |
| 撤销 | 问答不可答、旧引用 403、块计数 > 0（不阻塞） |
| 重建 | 该版本块计数 **0**、水位前移、旧引用仍 403 |

全量 `uv run pytest -q` → **598 passed**；ruff/mypy 全绿；演示环境重启后内部问答仍 `ANSWERED`。

## 4. 需要你判断的四点

1. **闸门只作用于公开内容**是否可接受？内部内容仍由状态/范围控制。
   若要求内部也并入水位，我需要改一批检索用例并确认"草稿可见性"口径。
2. **发布即推进水位**：新版本发布后，同租户此前已在流水线中、代更小但未发布的版本仍不可见。
   我理解这符合"未审核不提前可见"；若你希望"发布只切到自己那代之后的所有已 READY 代"，请指示。
3. **撤销后物理删除改为异步可调用**：当前是显式函数（测试/运维调用），**没有**定时 worker 消费
   `knowledge.version.revoked.v1`。是否要求本片补消费端（含重试/死信），还是留给 ADR-06？
4. **证据直读未加水位闸门**：证据服务用位置参数（`%s`）拼 SQL，与命名参数闸门不兼容，
   暂依赖"状态 + 重建删除"。是否要求本片必须补（我会把它改成命名参数）？
