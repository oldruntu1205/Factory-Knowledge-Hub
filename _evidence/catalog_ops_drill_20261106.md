# 运营演练：真实目录冲突的 KEEP / DROP_ALL 全流程

- 日期：2026-11-06
- 数据：本机测试库中"切片之前就入库"的 85 页目录版本（补录后 29 个待办组 / 62 条候选）
- 目的：不是再写测试，而是**用真实数据走一遍运营动作**，看问答在决议前后是否如预期变化

## 1. 演练前

```
待办组 29，候选 62
A112440 决议前：REFUSED / NO_EVIDENCE
A122430 决议前：REFUSED / NO_EVIDENCE
```

冲突货号在决议前**不对外作答**（不是"挑一条最像的"，也不是"用旧的先顶着"）。

## 2. KEEP（A112440，选 56.00 那条）

```
A112440 KEEP 后：ANSWERED
answer: A112440 的单价为 56.00（CNY），规格：400mm 38*500 24*24。
```

决议后立刻可答，答案里的价格与规格都来自被选中的候选，引用指向该候选所在块。

## 3. DROP_ALL（A122430）

```
A122430 DROP_ALL 后：REFUSED / NO_EVIDENCE
```

"该货号不设条目"是一个明确结论，不是遗忘——重抽取也不会把它再写回来。

## 4. 重抽取稳定性

```
重抽取：parsed=1314 inserted=0 duplicates=1253 conflicts=29 unsupported=28
决议状态：{'A112440': 'KEEP', 'A122430': 'DROP_ALL'}
条目：{'A112440': 1}          ← DROP_ALL 的货号没有条目
演练后：待办组 27，候选 58    ← 两个已决议组退出待办
```

即：**人工结论不会被自动流程改写**，已决议组也不再出现在待办里。

## 5. 运营导出

```
uv run python -m fkh.tools.catalog_conflicts --url <dsn> export \
    --tenant <uuid> --format md --out <path>
```

输出包含：待办组数、候选行数、以及每个候选的 `candidate_id / chunk_id / 规格 / 单价 / 原文行`。
演练导出 27 组成功；导出为**只读**，不改变任何决议或条目。

> 导出文件含客户价格，落在 `_corpus/`（gitignored），不进仓库。

## 6. 这次演练说明了什么

1. 争议价格**在决议前确实查不到**——不会拿旧值或猜测值糊过去；
2. 决议后**立刻生效**，且答案带原文引用；
3. DROP_ALL 是可持续的结论，重抽取不会"复活"它；
4. 待办数量会随决议减少（29→27），运营能看到进度；
5. 全链路**没有任何模型参与**（`generator=None`）。

## 7. 还没做的

- 没有"改判"入口（按 L1 裁决：错判走新版本）；
- 没有 Web 待办页（当前是 CLI 导出，能看能判，但不如页面直观）；
- 冲突只覆盖 `product_catalog` 域。
