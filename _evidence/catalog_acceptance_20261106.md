## 4. 描述类 RAG（当前不可交付）

8 条描述类问题（材质、标口范围、能否定制、含税、试管规格、塞子规格、索引页码、直形 vs 球形）：

```
ANSWERED 0/8    内容关键词命中 6/8    带引用 0/8    耗时 2.5–43s（首问冷启动明显）
```

**内容其实 6/8 是对的**，但模型**一条 `[evidence_id]` 都不给**，于是按现行严格规则
全部降级为 `REFUSED + 人工复核`。

为排除"只是这个模型不行"，同一批 4 个问题换了 3 个本地模型：

| 模型 | ANSWERED | 带引用 |
|---|---|---|
| qwen3:14b | 0/4 | 0/4 |
| qwen3:8b | 0/4 | 0/4 |
| qwen2.5:7b | 0/4 | 0/4 |
| qwen2.5-coder:14b | 0/4 | 0/4 |

**结论：不是单个模型的问题，是"每个句子都必须带 `[id]`"这一协议在 7B–14B 上不成立。**
模型愿意写答案，但不愿意在行文里逐个标注来源。

## 5. 三条可选路线（需要裁决）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 结构化引用块**（推荐） | 要求模型输出「答案正文 + 独立的引用清单」，覆盖检查改为"整体至少 1 条引用且每条都真实存在" | 严格度下降：不再逐句校验，"某句没引用"不再拒答；但伪造引用仍然拦得住 |
| B. 自动归因 | 模型只写答案，系统用文本匹配把证据挂到句子上 | 归因可能错挂，"看起来有引用"但支持关系是猜的；风险最高 |
| C. 暂缓 RAG | 描述类问答保持默认拒答，等 ADR-04 签署 + 更强模型 | 产品只剩"查货号/报价"，等于放弃知识问答主线 |

**我的推荐：A。** 理由：它保留了"引用必须真实存在、伪造即转人工"这条底线，
只把"逐句"放宽到"整体"，是对小模型能力现实的最小让步；B 会把可核验的证据关系变成猜的，
C 等于承认产品做不了问答。

## 6. 一句话总结

**能验收的：货号/报价（确定性、可引用、0 误答）；冲突治理（可见、可判、不可被覆盖）。**
**不能交付的：描述类问答**——卡在引用协议与本地小模型能力，不在检索与治理链路。
