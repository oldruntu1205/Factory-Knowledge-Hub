01 / BUSINESS CASE

为什么制造企业需要自己的 AI 知识中枢？

传统资料库解决“文件放在哪里”，企业知识中枢进一步解决“谁知道、是否可信、谁能用、如何持续复用”。

🧠

经验流失

老板与老师傅的判断依据散落在口头沟通和个人记忆中。通过语音访谈与审核，将隐性经验转为可追溯知识卡。

📚

培训周期长

新人反复询问相同问题，师傅投入大量时间重复讲解。岗位课程、带引用 AI 导师、考试与人工实操签核形成闭环。

🌍

客服响应不一致

产品参数、定制能力、材料与应用范围容易出现不同口径。外贸 AI 客服仅引用已批准公开的产品事实，复杂承诺转人工。

03 / SOLUTION ARCHITECTURE

混合部署：知识在企业控制之下，模型按策略调用

Obsidian 是知识编辑工作台，不是企业权限系统。知识必须通过审核、分级、版本发布后才能被 RAG 检索；外部 LLM 请求必须经过企业 AI Gateway。

企业私有域

核心知识资产不外流

原始录音、内部资料、用户身份、访问权限、知识索引、审批与审计默认保存在企业受控环境。敏感内容优先使用本地语音转写、Embedding 与重排。

公域模型按需接入

按知识分级使用外部 LLM

对外已批准公开的 C0 内容，可在合规与供应商策略允许时调用云端模型。C2–C4 明文默认不得外发；不满足条件时使用私有模型或拒答。

三年累计净现金流

计算口径与避免重复计数

年度知识检索节省价值 = 员工人数 × 每日节省分钟 ÷ 60 × 工作日 × 综合时薪 × 兑现比例。客服与培训的增量收益单独计入，但必须是未被前述员工节省时间包含的部分。三年净收益 = 3 ×（年度收益 − 年度运行费）− 一次性投入。三年 ROI = 三年净收益 ÷（一次性投入 + 3 × 年度运行费）。回本期以月度净收益为基础，若年度收益不超过运行费则无法静态回本。

该模型未计税费、融资成本、折现、业务增长、硬件残值与设备折旧税盾。实际财务立项建议进一步使用 NPV/IRR 和月度现金流模型。

05 / DEPLOYMENT TCO

私有部署 vs 公域 LLM vs 混合部署

将一次性硬件投入、模型 API 用量、运维成本放在同一套三年 TCO（总拥有成本）模型中。这里的“私有部署”指本地模型推理；“公域 LLM”指云端 API 推理。企业知识库和 ACL 在三种方案中都可以保留在私有域。

统一假设：36 个月，人民币，不含共同的知识中枢软件实施费、共同存储/数据库、税费及模型切换成本；公域输入、输出、缓存等复杂计价以“加权价格 × 合并系数”近似，需用供应商实际账单校准。

CLOUD API

公域 LLM API

—
36 个月推理相关 TCO · 不需要专门购置模型 GPU，但受 API 用量、价格、限流和供应商策略影响。
  • 初始硬件投入低
  • 按用量付费，易于扩容
  • 敏感资料不得未经批准外发
PRIVATE INFERENCE

私有模型推理

—
36 个月推理相关 TCO · 需考虑 GPU 采购、运维、可用性和本地模型效果。
  • 数据处理边界可控
  • 高负载下成本更可预测
  • 硬件闲置和模型维护是风险
RECOMMENDED ARCHITECTURE

混合部署

—
36 个月推理相关 TCO · 受控私有知识域 + 本地敏感推理 + 已批准请求的云端模型路由。
  • 按数据等级与任务路由
  • 平衡成本、性能与合规
  • 需建设网关和策略审计

06 / DECISION FRAMEWORK

什么情况下选择哪种模型部署？

决策因素公域 LLM API私有模型推理混合部署
初始资本开支低较高中等，可分阶段投入
用量波动适应强受 GPU 容量约束弹性与本地容量结合
敏感知识控制须严格限制外发较强，仍需内控按分级策略隔离
模型效果升级通常较快需要自行评测升级可按任务择优
网络依赖高可离线运行核心能力可设计为降级运行
适合业务已批准公开的产品问答敏感知识、内部培训多知识等级、多业务并存

本项目架构基线为混合部署，但是否采购专用推理 GPU 应由试点实际负载、数据分级、模型效果与 TCO 评估决定；不应先买设备再寻找使用场景。

07 / DELIVERY & ASSURANCE

从试点验证到企业级上线

阶段一 · 需求与数据

知识盘点与指标基线

明确产品范围、访谈对象、知识分级、岗位培训目标、客服人工转接规则；采集上线前处理时间和问题量。

阶段二 · 构建与联调

统一知识引擎

搭建采集、审核、版本发布、检索、引用、权限和审计；接入客服与培训应用；完成云端调用策略。

阶段三 · 试点与验收

效果与 ROI 复核

用真实业务问题测试准确性、引用、权限、转人工、培训结果；用实测数据替换 ROI 默认假设。

关键验收门禁

知识可信未审核内容不可进入正式问答；回答引用有效知识版本。
数据安全跨权限、撤销知识、内部报价等敏感资料不得泄露。
业务边界客服不自动承诺价格、交期、定制可行性；实操资格人工签核。

建议客户试点交付范围

产品知识选取 1–2 个产品系列，建立审核后的知识卡与问答集。
外贸客服完成中英文产品咨询、证据引用和人工升级流程。
新人培训选择外贸客服或产品技术岗位，建立课程、测验和学习记录。
经验采集完成老板或资深技术人员语音访谈与知识审批演示。
NEXT STEP

先验证价值，再扩大投入

建议从产品知识、外贸客服和新人培训的共同知识源启动试点，建立上线前基线与对照组。完成 4–8 周业务观察后，用真实节省工时、转人工率、客服正确率、培训达标率及实际 API 账单更新 ROI。
