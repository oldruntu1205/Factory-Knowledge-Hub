> 精度**不作达标认定**，客户语料阶段在评测前冻结人工标注规则与验收下限。

## 1. 结论先说

评测集：50 条中文问题；语料：本仓库 19 篇 Markdown（约 190 个 child 切片）；K=10；CPU。

| 召回方式 | recall@10（片段） | doc@10 | P@10（代理） | 平均耗时 |
|---|---|---|---|---|
| 词法（**AND**，2026-11-04 前） | 0.060（3/50） | 0.060 | — | 1.8 ms |
| **词法（OR，现行为 `lexical-v2`）** | **0.680（34/50）** | **0.800（40/50）** | 0.162 | 16.9 ms |
| 混合（BGE-M3 + 词法，RRF k=60） | 0.840（42/50） | 0.960（48/50） | 0.232 | 82.8 ms |

三条读数：

1. **词法缺陷已修**：字级 token 从 AND 改为 OR 后，同一份数据、同一批题的 recall 从 0.06 抬到 **0.68**，
   满足 L1 设定的回归门槛（≥33/50），原先命中的 3 条（L07/W04/P01）无退化。
2. **混合仍有增益**：相对 OR 词法 +16pp（0.68 → 0.84），doc@10 +16pp；代价约 5 倍延迟（17ms → 83ms）
   与一套模型依赖。是否默认开启，仍取决于客户语料与产品对口语化问句的要求。
3. **精度是短板**：P@10 只有 0.162（词法）/ 0.232（混合）——即 top-10 平均只有 1.6–2.3 条来自"含答案的那篇文档"。
   **精度下限尚未确定**（L1 要求在看到精度结果后再定），本轮不宣称精度达标。

## 2. 评测口径

- **K = 10**，与契约 `max_results` 默认值一致。
- **片段级命中**：top-10 任一命中块正文包含 `needle`（正确事实的关键串）。
  用「包含答案串」而不是绑定 chunk_id：切片参数一改，绑 id 的题集就整体失效，而且会奖励"切得碎"。
- **doc@10**：top-10 任一命中块属于 `needle` 所在文档。用于区分「没找回」与「找回但答案被切片边界切断」。
- **P@10 / 实际返回精度**：按**文档级相关性代理**计算——命中块是否来自含答案的那篇文档。
  这是代理指标，不是人工逐条相关性标注：同一文档内也可能有无关段落（**高估**），
  同一事实也可能分散在多篇文档里（**低估**），因此**不能等同真实相关性精度**；
  但两路用同一把尺，可做相对比较。空结果单列，不按 0 计入平均。
- 两路召回使用同一批入库数据、同一 ACL 主体（roles=staff）、同一 scope（internal_product）。

## 3. 语料与评测集（必须诚实标注的部分）

- 语料：`docs/**` + `README.md` + L1 架构契约（40KB），共 19 篇；child 切片约 190 个，全部写入 BGE-M3 向量。
- 评测集：`_evidence/recall_cases_20261104.json`，50 条中文问题，每条带 `needle`（脚本校验确实存在于语料）
  与 `doc`（所属文档）。
- **偏置**：问题是本项目的实施者写的，**不是客户问题**；语料是工程文档，不是玻璃仪器/工艺语料。
  因此数字只用于**同一语料下的相对比较**，不能当作客户场景验收值。
  真正的验收要按 `embedding-and-hybrid.md` §6 用客户真实资料与人工标注重跑。

## 5. 环境与已知限制

- 本机 `torch 2.15.0+cpu`、`sentence-transformers 6.2.0`、`transformers 5.22.1`；模型 `BAAI/bge-m3`（MIT，1024d）。
- CPU 推理：入库约 1–2 分钟/190 切片；查询 17ms（词法）/ 83ms（混合，含两路 + 融合 + 取文）。
- 权重缓存必须放**工作区内**（`.hf-cache/`，已 gitignore）：本机子进程写 `%TEMP%`/`D:`/`E:` 会被拒
  （`WinError 5`），HuggingFace 直连也不可用，只能用 `hf-mirror.com`。
- `BGEM3Embedder` 使用 `local_files_only=True`，离线可用；缺权重时报错而不是偷偷联网。
- 未做 rerank、未做多语种评测、未测客户语料；`n=50` 的置信区间很宽（±10pp 量级），
  只适合看方向，不适合单独用来卡验收阈值。

## 6. 建议（按性价比排序）

1. **客户语料验收**（现在最该做的）：用 50–100 条真实问题 + 人工标注正确片段重跑，
   并把精度口径从"文档级代理"升级为"逐条相关性标注"，否则无法回答"返回的这些到底相不相关"。
2. **决定混合是否默认开启**：修完词法后混合仍有 +16pp；若客户问句偏口语化，建议生产可选开启
   （保持 opt-in），但先要有客户语料数据支撑。
3. **观察词法 OR 的副作用**：常见字（的/是/在）会带来弱相关命中，P@10 0.162 已反映这一点。
   L1 已裁决本轮不加过滤阈值；如果客户反馈"搜出来一堆不相关"，再按 B 方案（匹配度阈值）另立切片送审。
4. 混合模式继续保持**服务端 opt-in、生产未授权**（L1 Q2）；本次实测不改变该结论。
