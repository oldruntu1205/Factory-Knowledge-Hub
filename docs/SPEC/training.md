# 培训规格

对应 L1 §13。覆盖「建课 → 绑定知识 → 出题 → 发布 → 分派 → 测验 → 进度」。

## 1. 状态与规则

| 对象 | 规则 | 由谁保证 |
|---|---|---|
| 课程发布 | 必须绑定至少一个**已审批**知识版本 | 数据库触发器（`FKH_COURSE_NO_SOURCE` / `FKH_COURSE_UNAPPROVED_SOURCE`） |
| 课程发布 | 存在 `DRAFT` 题目时拒绝 | 应用层（半成品题目随课程发布，学员看到的就是无依据的考题） |
| 课程发布 | `version` 自增、`published_at` 由数据库填写 | 触发器 |
| 分配 | 只有已发布课程可分配 | 应用层 |
| 分配 | 同课程同重复分配返回既有任务 | 唯一约束 + 应用层回查 |
| 测验 | 客户端不能提交分数 | 请求模型 `extra="forbid"`，多传即 422 |
| 测验 | 幂等键重复提交返回既有成绩 | 唯一约束 `(tenant, assignment, idempotency_key)` |
| 签核 | 学员不得自签 | 触发器 `trg_signoff_guard`（表已就绪，端点未实现） |

## 2. 判分

- 客观题（单选 / 多选 / 判断）自动判分；多选题**全对才得分**，不给部分分。
  知识考核里"漏选一半"与"全错"同样代表没掌握，部分分只会让及格线难以解释。
- 主观题（简答）挂起，`grading_status` 置 `PENDING`，等人工复核。
- `objective_score` 只在有客观题时才有值；全是主观题则为 `null`，不是 0。
  0 分与"未判分"是两件事。

## 3. 一个真实的坑：题目版本

课程 `version` 在发布时自增（触发器行为），而题目按创建时的版本号入库。
若判分按「课程当前 version」查题，题库会整体落空，表现成"交了卷但没有任何题目被判定"。

处理：判分取该课程**全部** `APPROVED` 题目，不按版本过滤。
题库在同一时刻只有一个活跃版本（题目一经审批不再修改），历史追溯靠
`attempts.course_version` 记录提交时用的是哪一版课程。

这条由 `test_full_training_flow` 固定：修复前该用例的 `objective_score` 为 `None`。

## 4. 学员身份

一律取令牌的 `sub`（外部主体），**不接受**请求体或参数指定学员：

- 培训对象可能尚未同步进 `principals` 表，用内部 id 会把没开通账号的人挡在门外；
- 若允许客户端传学员标识，改一个字段就能提交他人卷子、查他人成绩。

`training_assignments.learner_subject_id` 存的就是这个外部主体。

### 5.1 正文本读取（`GET /v1/training/assignments/{id}/content`）

- 权限：`learner`；任务必须属于令牌主体（他人/不存在同码 403）；
- 可见性是**交集**：课程 `PUBLISHED` ∧ 版本属于课程源 ∧ 内部身份 ∧ `audience=internal` ∧
  `status=APPROVED_INTERNAL` ∧ `required_scope` 被 `allowed_scopes` 覆盖 ∧ 块 ACL 允许；
  父块只有在其**全部子块**都通过 ACL 时才返回全文（防"用父块绕过行级 ACL"）；
- 源版本一旦进入禁止状态（撤销/弃用/待复核）→ **整课 409**，不返回残缺课程；
  分级 C3+ 暂无学员授权口径，同样整课 409；
- 分页 `limit` 1–20（默认 5），`cursor` 为 **HMAC 签名**的位置声明，绑定租户/主体/任务/课程修订，
  篡改、跨主体或跨任务复用、过期 → 409；每页重新校验，旧游标不保留撤销前的读取资格；
- 每次成功读取落一条 `training_content_access_log`（主体、任务、课程修订、返回的版本与块、trace），
  **不记正文、令牌或原始游标**（迁移 `0020`）。

## 7. 三通道一致性（2026-11-08 修复）

**问题**：培训问答此前只限制了检索通道（`version_ids`），但**目录精确通道在检索之前运行**，
既不接受课程来源限制，也不看分级。复现（基线 `1b1701d`）：学员在课程 A（检验规范）的任务里问
`A112420 的规格是什么？` → 返回 `ANSWERED`，答案「A112420 的规格为 200mm 38*300 24*24；单价 39.00（CNY）」，
引用指向**课程 B** 的目录版本。C3 课程源同理：正文读取 409，问答却仍能答。

**修复**：`AnswerService.answer(only_version_ids, max_classification)` 把两个约束**同时**传给：
1. 检索通道（已有 `version_ids`）；
2. **目录精确通道**（`find_catalog_item` 新增 `version_ids` 与 `max_classification` SQL 条件）。

培训侧 `approved_source_versions()` 同时按 `classification <= 2` 过滤；若课程源含 C3+ → 整课视为不可用
（与正文读取的 409 一致），问答返回 409。

**验收**（`tests/e2e/test_training_scope_unified.py`，真实 PG + 业务角色 + HTTP，3 条）：
- 课程 A 里问课程 B 的货号 → 非 ANSWERED、不含规格/价格、引用不含 B 版本；
- 本课程问题仍 ANSWERED，且引用集合恰好等于课程 A 的来源；
- 目录通道**确实被走到**（审计 route 为 `catalog_exact`/`handoff`），不是被别的分支遮住；
- C3 课程：正文 409 且问答 409。
