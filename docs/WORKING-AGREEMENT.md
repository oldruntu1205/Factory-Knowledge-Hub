# 并行开发约定

适用范围：同一仓库上并行推进的 lane（人工开发、DSH 或其他代理）。
本文件只写规则，不写状态；状态见 [`HANDOFF.md`](./HANDOFF.md)。

## 1. lane 划分

每个 lane 是一条可独立验收的纵向切片，边界按"能单独演示的业务动作"划，不按代码目录划。

已存在与规划中的 lane：

| Lane | 验收动作 |
|---|---|
| A · 采集与治理 | 上传文件 → 得到可审核草稿 → 审核发布撤销 |
| B · 事件投递 | 发布/撤销产生的事件被投递、失败进死信、可重放 |
| C · 证据定位 | 凭 evidence_id 取回受控证据 |
| D · 检索与问答（规划） | 问一个问题，得到带引用的回答或明确拒答 |
| E · 培训（规划） | 新人分配课程 → 学习 → 测验 → 导师签核 |

一个 lane 只改自己范围内的业务语义；共享契约（见 §4）的改动必须走 §5。

## 2. 迁移编号

- 编号先到先得，**占号必须在 `docs/HANDOFF.md` 迁移台账登记**，写清内容与状态；
- 已应用的迁移文件**不得修改**，`migrations/apply.py` 会做校验和比对并拒绝执行漂移的历史；
- 只有编号连续的迁移可以顺序应用，跳号会留下空洞，回滚演练会失败；
- 预留号（如 0007）只能由登记它的 lane 使用，其他 lane 从当前最大号 +1 开始。

## 3. 跨 lane 改动

允许，但必须同时满足三条：

1. **提交信息里写明"跨 lane 说明"**：改了什么、为什么这个改动属于本 lane 的前置条件、
   对应哪条裁决或哪条约束；
2. **补回归用例**：跨 lane 改动必须在改动方自己的测试里覆盖，不能只靠对方测试兜底；
3. **不改变对方的业务语义**：可以加参数、加字段、加顺序键，不能改变既有判断结果。

示例（已发生，可作为模板）：

> 跨 lane 说明：`src/fkh/domain/review.py` 的 ordinal 映射是 outbox 顺序键的前置改动，
> 由 L1 判决第 4 条要求（生产者显式给出同版本内的事件顺序），回归用例见
> `tests/e2e/test_outbox_ordering.py`。

反向也成立：发现对方 lane 的缺口（例如鉴权上下文缺字段），**在自己的提交里修，不改对方代码**，
并在提交信息里说明接触面。

## 4. 共享契约（单一来源）

| 资产 | 位置 | 谁可以改 |
|---|---|---|
| HTTP 接口 | `contracts/openapi/openapi.yaml` | 改动端点的一方，必须同步契约 |
| 请求/响应 Schema | `contracts/schema/*.json` | 同上 |
| 事件类型与信封 | `contracts/schema/event_envelope.json` | 事件生产方 |
| 数据库结构 | `migrations/*.sql` | 见 §2 |
| 状态机 | `domain/state_machine.py` + 触发器 | 必须裁决后改，见 §5 |

契约改动与代码不同步会被 `tests/contract` 直接抓住（代码路由与 `openapi.yaml` 双向比对）。

## 5. 必须先裁决的事

以下改动不得由实施方自行决定，必须先拿到 L1 判断：

- 状态机新增状态或迁移；
- 新增数据分级（C0–C4 之外）或改变公开发布条件；
- 引入外部模型调用、跨境传输；
- 改变"撤销立即生效"的语义；
- 改变错误码语义（例如把 403 改成 404）。

送审格式：`_evidence/l1_request_<topic>_<date>.md`，只陈述事实与待判选项，不夹带结论；
回复归档为 `_evidence/l1_reply_<topic>_<date>.md`，落实情况写进对应 `docs/SPEC/*.md` 的判决登记表。

## 6. 门禁

合并到 `main` 前四条必须同时满足：

```bash
uv run pytest -q                        # 全绿，且不能有 skip
uv run pytest -q -m requires_pg         # 数据库门禁真实执行
uv run ruff check src tests migrations  # 无告警
uv run mypy                             # strict，无错误
```

P0 类失败一律视为阻塞，不允许用"平均分"掩盖单点失败。
数据库测试出现 skip 等于未验证，必须在有数据库的环境补跑后才能合并。

## 7. 分支

当前为单人单机直推 `main`。并行 lane 超过两条时改为：

- `feat/<lane>-<topic>`，一个 lane 一个分支；
- 迁移文件按 §2 先占号再提交，避免 rebase 时撞号；
- 合并前由另一条 lane 的执行方跑一次门禁（交叉验证），结果写进 PR 描述。

## 8. 文档位置

| 类型 | 位置 | 更新时机 |
|---|---|---|
| 状态快照 | `docs/HANDOFF.md` | 每个 lane 完成或裁决落地时 |
| 领域规格 | `docs/SPEC/<topic>.md` | 实现与规格不一致之前 |
| 审查请求与回复 | `_evidence/` | 送审与收到回复时 |
| 架构决策 | `docs/ADR/` | 决策变化时 |
| 门禁证据 | 测试文件本身 | 持续 |
