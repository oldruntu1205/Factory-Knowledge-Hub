## 踩过的坑（复用价值高）
1. plpgsql `RAISE ... USING ERRCODE` 只接受 5 位 SQLSTATE，写 `'check_violation'` 建函数时直接失败，必须用 `'23514'`/`'23503'`/`'42501'`。
2. `SET LOCAL app.tenant_id = %s` 不支持参数绑定，必须 `SELECT set_config('app.tenant_id', %s, true)`。
3. PG 视图默认可绕过基表 RLS，必须 `WITH (security_invoker = true)`。
4. FastAPI `create_app(custom_settings)` 若不 `dependency_overrides[get_settings]`，鉴权依赖会读进程级缓存配置，导致所有请求 401。
5. 测 RLS 必须 `SET ROLE` 到无 BYPASSRLS 角色；用超级用户测等于没测。
6. pgcrypto 在精简实例可能缺失，迁移应改为「可用则装」；PG13+ 已内置 gen_random_uuid。

## 追加：解析与切片（commit 16248f2）
- 解析：markdown-it-py / pdfplumber / python-docx / bs4 / csv 标准库，统一 `parse_document()` 分派。
- **PDF 选 pdfplumber 不选 PyMuPDF**：后者 AGPL-3.0，闭源商业交付有传染风险；pdfplumber 是 MIT 且能给坐标+表格。
- 复核原因封闭枚举 ReviewReason：CROSS_PAGE_TABLE / TABLE_STRUCTURE_UNCERTAIN / MISSING_UNIT /
  EMPTY_DOCUMENT / HEADING_HEURISTIC / PARSER_FALLBACK / LOW_OCR_CONFIDENCE。
- 扫描件不静默降级，标 PARSER_FALLBACK 进复核队列；OCR 待 ADR-05。
- 切片：approx-cjk-v1 近似 token 计数；`section_break_level=2` 按一二级标题分组。
- 实测（用仓库 40KB L1 契约文档）：逐标题切 59 parents / median 132 token；按一二级分组 17 parents / median 502，child 中位数 344 落入 250-450。
